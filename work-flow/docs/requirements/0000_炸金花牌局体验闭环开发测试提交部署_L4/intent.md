# 炸金花牌局体验闭环任务意图

## 目标

依据 `docs/superpowers/specs/2026-08-19-zhajinhua-gameplay-closure-design.md` 完成牌局规则、生命周期、WebSocket、排行榜、补豆和前端交互闭环；完成白盒、API、真实 WSS、黑盒和浏览器自动化验证；提交并推送至 `SorryMcDonald/SorryMcDonald.github.io` 的 `huang` 分支；最后部署到 `crazythursdayplay.bbroot.com`。

## 验收范围

- 六个固定座位，2–6 人开局，每个普通玩家本地视角始终处于正下方。
- 默认暗牌、看牌不推进、明牌双倍费用、多轮下注、合法加注、手动比牌目标、独立亮牌和结算公开。
- 60 秒行动超时、60 秒全连接断开宽限、多标签页连接计数、空房立即回收。
- 玩家聊天、观战只读、每秒一次、120 字、最近 20 条、纯文本和内存生命周期。
- 精确手输确认后按固定横幅、补豆、排行榜横幅顺序补到 100,000 豆。
- 财富榜、赌神榜、散财榜及大富翁、穷乞丐和牌局多称号展示。
- 轻量、影视、关闭三种比牌效果以及音乐、音效和倒计时反馈。
- 原有测试无回归，新增白盒、HTTP、WSS、黑盒、Playwright 和 Browser 真实复核全部通过。

## 发布边界

- 远端只写 `huang`，不修改 `main`。
- 发布前保留可恢复的应用备份和上一版本引用；失败即回滚并重新验证健康状态。
- 不把密码、令牌、私钥、会话、环境文件、数据库、日志、缓存或本机临时材料写入 Git、工作流证据或命令参数。
- 不改变现有 AI 平台 Nginx/Cloudflared 路由；发布后独立确认其健康状态。
